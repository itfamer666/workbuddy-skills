# 调研手法手册

目标：在 1~2 小时内，把一个陌生企业从"只知道名字"摸到"能和董事长对话"的程度。

---

## 一、三条信息渠道的优先级

| 优先级 | 渠道 | 价值 | 风险 |
|---|---|---|---|
| 1️⃣ | **官网隐藏数据接口** | 结构化、实时、准确 | 需要挖掘，有时需鉴权 |
| 2️⃣ | **官网全站页面**（含子栏目） | 官方口径、战略表述原文 | 文案可能过期，不同页面自相矛盾 |
| 3️⃣ | **公开报道 / 百科 / 工商信息 / 供应商案例** | 补充管理层、营收、荣誉、IT 供应商 | 准确性参差，需交叉验证 |

**核心原则：接口数据 > 网页文案 > 第三方报道。** 对外一律只用官网口径。

---

## 二、标准流程

### Step 1 · 全站侦察（跑脚本）

```bash
python3 scripts/recon.py <网址> -o ./调研
```

会输出：`raw/`（原始页面与 JS）、`api/`（命中 JSON 的接口）、`endpoints.txt`、`recon-report.md`。

**必须先读 `recon-report.md`**，它会告诉你哪些接口命中了、各自多少条数据。

### Step 2 · 读页面正文

```bash
python3 scripts/html_to_text.py ./调研/raw -o ./调研/pages.txt --dedupe
```

`--dedupe` 会剔除各页重复的导航与页脚，让每页只留独有正文。文本很长时分段读。

### Step 3 · 读接口数据

`api/*.json` 用 Read 直接看。接口里的**门店 / 网点 / 品牌 / 产品线 / 区域**这类数据，
应优先用于定量章节 —— 它们比网页上"400+家门店"的宣传文案准确得多。

### Step 4 · WebSearch 补充（按这个清单搜）

针对同一家企业，分别搜索以下主题，每类搜 1~2 次：

1. **管理层**：`<公司> 董事长 总经理 总裁 投资人` → 拿到姓名、职务、家族/职业经理人结构
2. **年度会议**：`<公司> <今年> 年会 / 半年会 / 工作会` → **最高价值**，能拿到管理层原话和当年战略
3. **财务与榜单**：`<公司> 营收 百强 排名` → 体量、行业地位（注意榜单口径）
4. **IT 供应商案例**：搜 `OA`、`CRM`、`数字化` 供应商官网的客户案例页 → 能反推他们用了什么系统
5. **工商信息**：法人、注册资本、成立日期、股东结构
6. **近期动态**：周年庆、战略合作、新品发布 → 天然沟通契机

> **第 2 条最重要。** 搜"年会""半年会""收心会""工作会"，往往能找到官方公众号的详细报道，
> 里面有各位高管的发言原话。**这些原话是 AI 方案立项的最佳依据。**

### Step 5 · 交叉核对，列出口径差异

把同一指标在不同来源的值列成表（客户数、门店数、营收、员工数经常对不上）。
**这份差异表本身就是报告第 12 章的内容**，也可以作为开场话题（"这恰恰说明数据治理有问题"）。

## 三、踩过的坑

### 坑 1 · WebFetch 拿不到内容

现代官网大量使用 JS 渲染。典型症状：WebFetch 返回 `API接口单元`、`loading`、或极短正文。

**解法：永远用 `curl -sL` 带浏览器 UA 抓原始 HTML。** `recon.py` 已经内置，
它还会检测是否为 JS 渲染页并在小结里提醒。

### 坑 2 · 真正的宝贝藏在接口里

官网宣传文案常写"30+ 品牌 / 400+ 门店"，但**接口里往往有精确清单**。
挖掘办法：下载站内所有 JS，用正则找 `url:"/xxx"`、`$.get("/xxx")`、`fetch("/xxx")` 形态的路径，然后逐个 GET 试。
`recon.py` 自动完成这一步并只保留返回合法 JSON 的。

**实测经验**：这类清单型接口（园区/门店/品牌/产品线）常无需鉴权，且返回结构完整，含地址、经纬度、电话。

**接口返回空 ≠ 没有数据。** 新闻列表、留言、黑名单这类后台接口，默认 GET 通常返回
`{"code":1,"data":[]}` —— 必须 POST 且带 `pageNum`/`pageSize` 才吐数据。
`recon.py` 的第二遍「补参再探」会自动试 4 种调用方式，救回来的接口会在小结里写明调用姿势。
若仍为空，多半需鉴权或必填业务参数，可看 JS 里该接口附近的调用代码手工补参。

另外注意**接口命名成对出现**的规律：`xxxList` 通常是全量清单（价值高），
`getXxxList` 常需分页参数，`allXxx`（如 `allProvince`、`allCarBrandLetter`）多是全量字典表。

### 坑 3 · 子栏目比首页有料

首页通常只有宣传语。**务必遍历导航里的每个二级栏目**（关于我们、业务板块、新闻、社会责任、人力资源等）。
`recon.py` 会自动抓，但**注意 max-pages 别设太小**。

### 坑 4 · 别只搜公司名

`<公司名> 数字化`、`<公司名> AI` 这类搜索经常搜不到东西。
更有用的是搜 **供应商案例**（致远、用友、金蝶、Salesforce、丰车等供应商的客户案例页），
以及搜 **行业协会榜单**。

### 坑 5 · 第三方榜单要谨慎

同一家企业可能出现在"民营百强榜""社会责任榜"但不在"营收总榜"里。
**对外沟通不要主动提排名**，以对方自述为准。

## 四、产出前自查清单

- [ ] 所有数字标注了来源（官网 / 接口实测 / 第三方）
- [ ] 接口实测数据与网页文案不一致的地方已列出
- [ ] 管理层姓名职务至少交叉验证过一次
- [ ] 找到了对方本年度的战略关键词（最好是原话）
- [ ] 找到了至少一条关于其 IT 系统/供应商的证据
- [ ] 识别出唯一的"否决点"人物（通常是 IT / 风控负责人）
