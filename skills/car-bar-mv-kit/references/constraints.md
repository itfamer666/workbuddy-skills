# 已验证约束与失败路线

本文件记录 2026-11-07 五轮实测结论。**这些是硬事实，不是推测**，执行时不要重新试探。

---

## 1. 视频分辨率：1080p 必被拒

图生视频接口的 `resolution` 只接受 `768P` / `2K`。提交 `1080p` 返回：

```
status=400 code=14407 Create video failed with error:
unsupported video resolution: 1080p, supported values: [768P 2K]
```

改用 `2K` 一次成功。实测成片为 **2560×1440 / 24fps / 5.17 秒 / 124 帧 / H.264**。按报错修正即可，不要换数值反复试，也不要把 `1080p` 写进提示词假装满足。

## 2. 服务侧音轨：提示词关不掉

两段成片都自带 **非静音 AAC 音轨**（32 kHz 立体声）：

| 片段 | mean_volume | max_volume |
|---|---|---|
| 女歌手版 | -9.0 dB | 0.0 dB |
| 男歌手版 | -8.3 dB | -0.3 dB |

男歌手版曾额外写入 `Do not add any music, vocals, or audio track — the clip must be silent`，结果仍带音轨，证明提示词无效。语音转录女歌手版得到约 4.4 秒无实际语义的不通顺中文碎片，说明既不是用户指定音乐，也不是可控人声。

**结论**：音轨由服务侧固定附加，交付时必须提示后期静音或替换；不要宣称是「无声片段」。

## 3. 静态图右下角角标：提示词消不掉，靠本地修补

静态图固定被叠加服务侧角标；实测亮色包围盒 **`(1913,1084)–(2036,1140)`**（2048×1152 图上）。提示词写「bottom-right corner must remain pure dark background」无效。**视频不带该角标**，抽帧放大复查右下角为连续深色地面。

修补算法（已验证，见 `scripts/remove_corner_badge.py`）：
1. 保守修补区取 `x ≥ 0.916W`、`y ≥ 0.918H` 至图像边界（2048×1152 对应 1876 / 1058），留足余量覆盖第二行小字。
2. 取修补区左侧同尺寸暗部纹理，水平翻转后平移填充。
3. 与原图 30px 高斯低频基底按 0.34 混合，保留局部明暗趋势。
4. **羽化只放左 / 上边界；右 / 下贴图像边界必须全强度替换**。第一版四周都羽化，导致第二行小字残留。
5. 判据：修补区亮度 >42 且近中性的像素数归零（实测 3420 / 3320 → 0），再放大复查无笔画残留、无方块痕迹、无接缝。

## 4. 像素级抠图合成：已验证失败，禁止使用

输入实拍车图为 618×459、白天户外平光、柏油停车场；目标舞台是暖金夜景、圆形展台带倒影。抠图贴入后出现三类问题：旧车区域背景重建留下**硬矩形边界**、一块**暖色模糊斑**、白色车身**偏亮贴片感**。

改用「双图参考 + 原生重绘」一次达标：光影、接触阴影、地面倒影、透视自然，无白边与补丁。低分辨率或光照不匹配的实拍素材一律走 AI 融合。

## 5. 中文牌照小字不可精确还原

AI 重绘能还原车标形态与白色牌照板，但牌照框上中文小字会变成不可辨的伪文字。生成前须让用户选择「去掉标与牌照文字」或「保留形态、接受文字不可读」；若要求 100% 可读，只能局部后期贴图（不属本技能范围）。

## 6. 跨片段车辆漂移：实证结论

取两段视频 `t=2.5s` 车区域并排对比：男歌手版的车身占比更大、车头更正面、前脸光斑位置不同、牌照伪文字也不同。原因是两条视频独立生成，参考图只能逼近，做不到严格同一。

**剪辑规避**：当作独立分镜，中间加叠化 / 闪白 / 遮挡转场，或用「歌手特写 → 切回全景」景别切换掩盖；不要在同一镜头内硬切，也不要向用户宣称两段可拼成连续镜头。

## 7. 成套一致性靠锚点链，不靠并行

- 女歌手版立锚 → 男歌手版以该图**单张**派生；派生时不要再传车图，否则二次重绘导致车辆漂移。
- 车辆全特征写成 ABSOLUTE INVARIANTS 逐项锁死。
- 禁止两张图并行独立生成。
- 用户主动换风格＝作废旧锚点、重立新锚点，不沿用上一套参考图；换风格后两版之间车造型与乐队站位会有差异，但每版内部两张严格一致。

## 8. 人物中国面孔的写法

主唱与四位乐手都要显式写「自然东亚骨相、黑发、深褐眼、自然中国肤色」，并排除「混血 / 欧美化 / 高加索骨相」。只读回验收，不凭提示词推断；实测该写法未产生刻板化混血脸。

## 9. 口型与音乐的能力边界

当前视频生成无音轨输入，只能做自然演唱嘴部开合、呼吸与身体律动，**无法与指定音乐逐字对齐**。生成前须由用户明确接受此限制，不得静默降级。配乐、精对口型、成片合成在剪辑环节完成。

## 10. 计费与算力口径

一次完整运行（2 图 + 2 视频）的**计费生成调用 = 5 次**：

| 调用 | 用途 | 是否交付 |
|---|---|---|
| 1 | P1 场景锚点（文生图） | 中间产物，不交付 |
| 2 | P2 双图融合 → 女歌手成品图 | 交付 |
| 3 | P3 派生 → 男歌手成品图 | 交付 |
| 4 | P4 女歌手版 5 秒视频 | 交付 |
| 5 | P4 男歌手版 5 秒视频 | 交付 |

若用户只要 1 段试片，则为 4 次；被拒的 `1080p` 提交不产生有效生成，但不要靠重复试探消耗次数。

**积分**：系统未提供积分余额或账单查询能力，无法给出精确积分数值。记录时只写「实际计费生成调用次数」，并如实注明「无法获取精确积分数，需用户提供账单」，**不得编造数字**。

## 11. 本地环境（macOS / Apple Silicon）

- Python 3 + Pillow 可用；**无 NumPy、无 OpenCV**，修补脚本用纯 Pillow 实现。
- `ffmpeg` 位于 `~/.local/bin/ffmpeg`；**无 ffprobe**，用 `ffmpeg -i` 读元信息。
- 画布写入用 `.miora`，成片副本在同级 `<画布名>_assets/`；`present_files` 只能用画布返回的 `copied_assets` 路径，不能用生成工具的隐藏目录 `localPath`。
